# P9 predictions: serving noise floor

Written 2026-11-11, before any P9 run.

## Change from the plan (please confirm)

The plan says "same task, same seed, same prompt, rerun 3 times". On these servers SGLang ignores the
`seed` field (two requests with seed=1 gave different answers on 2026-11-11). At temperature 1.0 a
"same seed" rerun is therefore just another random sample, and P9 would measure the same thing as P1.

To measure serving noise alone, P9 uses **greedy decoding (temperature 0)**, everything else as in P1:
- 3 tasks: sf_tf01_goal_imbalance, sf_tf03_correlation_causation, blade_crofoot.
- 3 reruns per task sent together, so they share batches with each other (production batching).
- 1 more run per task alone on an idle server, one request at a time (batch size 1).
- 12 runs in total.

With greedy decoding, any difference between reruns comes from the server (batch composition,
floating-point order), not from sampling.

## Expected direction

1. The 3 greedy reruns of a task are not all identical: they first differ somewhere after the first
   few hundred tokens, and once they differ the runs drift apart (different code, different steps).
2. Decision agreement across the greedy reruns is higher than in P1 at every decision type, and
   answer consistency is higher than in P1.
3. The batch-size-1 run differs from the batched reruns about as much as they differ from each other.
4. framing.target agrees fully (the target is given in the task); variables / transformation /
   model.controls are the first to differ when anything differs.
