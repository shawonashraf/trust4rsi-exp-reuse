# P1 predictions: divergence census

Written 2026-11-11, before any P1 run.

Run: 15 tasks x 5 runs, no memory, no hint, temperature 1.0 (seed field ignored by the server, so
the 5 runs differ by sampling). Metrics as in quick_runs.md §2, computed by quick_runs/metrics.py on
the executed decisions (post-hoc extractor, temperature 0).

## Expected direction

1. H1: disagreement concentrates at a few decision types. Lowest agreement at transformation,
   model.controls and variables (P-G04a); highest at framing.target (given in most prompts) and,
   for Silent Failures, model.family (the prompt often names the model).
2. At least half of the tasks first diverge at one of the first two decision types the runs state.
3. Silent Failures: consistent failures (all 5 runs fail the same check) on TF03 (column_x kept)
   and TF05 (leakage columns used), as in the paper where every configuration failed these tests.
   TF01 resampling / class weights mostly fail in all runs as well. TF02 (messy values) is split:
   some runs clean the values, some do not.
4. The *_cue variants (file names naming the pitfall) fail less than their leak-free twins on TF04
   (torque features) and TF06 (selection metric).
5. BLADE: answer consistency on (direction, supported) is high (at least 0.6 pooled), while
   model.controls agreement is low. That is, runs reach the same verdict by different analyses.
6. Silent Failures numeric answers (test metric to 3 significant digits) agree less often than BLADE
   verdicts, because small preprocessing differences change the number.
7. Stated vs executed: on at least one decision type per task, some run states one value and executes
   another (as in the smoke run, which stated Negative Binomial and fitted Poisson).
