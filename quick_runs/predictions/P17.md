# P17 store written without a checker: what does the agent's own memory teach it, and does the guide filter it?

Written 2026-11-17, after P16 and before any P17 run. Asked for by the author (2026-11-17: "afterwards, run P17").
Earlier that day I had proposed P17 as "an evolving store where the agent writes lessons without evaluator feedback
and the guide judges them". This file fixes the design before the runs.

## Why

This addresses review weakness 5. The P12 store is the best case for memory: after each run, the writer was told
which pitfall checks failed. A self-evolving agent without an external checker does not get that. Its silent
failures look like successes to it (the code runs and gives a score), so its lessons may encode the failure.
Examples: "keep all numerical columns as instructed", "coerce height to numbers". Lessons like that would be wrong
lessons that agree with the instructions. P16 showed that the guide passes those every time. P17 asks whether this
happens with lessons the agent writes itself, not ones I planted.

## Method (one change from the P12/P13 store; everything else as P13 and P16)

1. **Write ("nf" lessons).**
   - Writer: the P12 writer (`quick_runs/p12/lessons.py`, Gemma 4 31B, thinking off, temperature 0, 1-3 lessons
     per run).
   - Source runs: the same 40 runs as before (P1, no memory, 5 runs on each of the 8 Silent Failures task
     variants).
   - The only change: the "Evaluation of this run" section is removed from the writer prompt. The writer sees only
     the task and what the agent did.
   - Output: `quick_runs/results/P17/lessons_nf.jsonl`, frozen once written.
2. **Store "nf".** The 708-lesson store with every Silent Failures lesson (99 lessons) replaced by the nf lessons
   from the same runs. BLADE and DSBench lessons are unchanged.
3. **Label before any guide or agent run.** I read each nf lesson for the 4 failing tasks and label it:
   - **fix:** it tells the agent to do the pitfall's fix. That is: check class balance or weight or resample (TF01);
     strip a unit suffix from height (TF02); exclude `column_x` or select features by causal reasoning (TF03);
     drop leaking columns (TF05).
   - **reinforcing:** it tells the agent to do what fails the check. That is: use the plain split or no weighting
     (TF01); coerce height to numbers without stripping, or drop it (TF02); keep all numerical columns, or keep
     `column_x` (TF03); use all features, or keep the spending columns (TF05).
   - **neutral:** anything else.

   Labels go in `quick_runs/p17/labels_nf.yaml` and are committed before stage 3.
4. **Arms** (6 tasks, 5 runs each, the agent as in P13):
   - **C1-nf:** all of the task's own nf lessons in context (the nf counterpart of P12's C1, 0.75).
   - **E-nf:** embedding top-3 on the nf store (counterpart of P13 E, 0.475).
   - **G3-nf:** the P13 guide, R = 3 (counterpart of G3, 0.50).
   - **G3d-nf:** the P16 data-profile guide (counterpart of G3d, 0.60).

   That is 60 guide runs, 120 agent runs and 40 writer calls. On two 2-GPU servers, if two pairs are idle, it takes
   about 1.5 hours.

## Expected direction

1. **Few fixes without a checker.** Across the nf lessons for TF03 and TF05, at most 2 are labelled fix. For TF01
   and TF02, at most half of the nf lessons are labelled fix.
2. **Lessons that encode the failure.** At least 4 nf lessons for the 4 failing tasks are labelled reinforcing.
3. **Own lessons no longer help.** C1-nf pooled targeted checks are at most 0.25 (C1: 0.75; no memory: 0.075).
4. **The guide keeps reinforcing lessons.** In G3-nf, a reinforcing lesson is shown in at least half of the runs in
   which one is among the guide's candidates.
5. **The profile filters some.** G3d-nf shows a reinforcing lesson in at least 3 fewer of the 20 failing-task runs
   than G3-nf.
6. **No harm on the easy tasks.** TF04 and TF06 are within 0.01 of A0 in every nf arm.

## What each outcome means for the paper

- **1-4 hold:** without a checker, the agent's own memory mostly contains instruction-agreeing lessons that encode
  its silent failures, and an instruction-ranking guide keeps them. The trust problem in P16 then also occurs
  naturally, not only with planted lessons. Review weakness 5 is answered with data.
- **1 fails:** the agent can find some fixes from its transcript alone. That would be good news for memory without
  a checker, and the paper would say so.
- **5 holds:** the profile is a useful check even on lessons the agent wrote itself.

## Limits stated in advance

- 1 generation of writing (the store does not keep updating during the agent runs), 40 source runs.
- The labels are mine, but they are made before any guide or agent run, and the rule is fixed above.
- The other tasks' lessons keep their evaluator-informed versions, so the store is only partly checker-free.
