# P13 guided retrieval: does a guide that judges usefulness after retrieval fix what similarity misses?

Written 2026-11-15, before any P13 run. Predictions 1, 2 and 5 revised the same evening after a retrieval-only
dry run (no agent or guide calls), before approval. Asked for by the author (2026-11-15) for a 4-page short paper at the AAAI 2027
Workshop on Trustworthy Evolution of AI Agents (deadline 2026-11-20 AoE). Design, guide prompt, wrong lessons and
predictions approved by the author as written (2026-11-15, "Yeah do it").

## Idea to test

Similarity retrieval tells us which stored lessons look like the task. It does not tell us which ones help. In
P12 the store held the lessons that fix the planted problems (all own lessons in context: 0.75 of targeted
check-runs passed), but BM25 top-3 picked near-duplicates and one contradicting lesson (0.125; no memory 0.075).

P13 adds a **guide** after retrieval: the same model reads the task and the retrieved lessons, says which are
useful, and, if what it has is not enough, writes a new search query so retrieval tries again. The number of
retries is a test-time budget: more retries, more of the store examined. If the idea holds, usefulness-guided
retrieval closes most of the gap to the in-context upper bound, and more budget helps.

Second question (trust): the agent follows a wrong note in the prompt (P4: 20 of 20). Does the guide keep planted
wrong lessons out, or does it pass them on because they look task-specific?

## Method (code: `quick_runs/p13/`)

Store: the same 708 frozen P12 lessons (written by the agent from its P1/P1b runs with the evaluator's outcome).
Poisoned store: the same plus 12 hand-written wrong lessons (`quick_runs/p13/wrong_lessons.yaml`), 3 per failing
task, labelled as coming from an earlier run of that task. Each repeats the P4 wrong hint (drop a useful column).

Retriever (ReasoningBank-style): dense embeddings (Qwen3-Embedding-0.6B, on CPU), cosine similarity. Each lesson is
keyed by its source task's question plus its text, as in P12. Query: the task question.

Guide (gemma-4-31B, same sampling as the agent: temperature 1.0, thinking on). One call per round. Input: the task
question, the data schema (what the agent sees too) and the candidate lessons (title, when, content). It never sees
outcomes, scores, checks or gold answers. Output JSON: for each candidate `useful: true/false` with a one-line
reason; `enough: true/false`; if not enough, `query`: a new search text for what is missing. Prompt in
`quick_runs/p13/guide.py`. The guide is told a lesson is useful only if it applies to this task and data and is
consistent with the schema; it is not told that wrong lessons exist.

Loop: round 0 retrieves the top 5 by similarity. Each retry retrieves the top 5 for the guide's new query, skipping
lessons already shown. Stop when the guide says enough or the budget is spent. The agent gets up to 3 accepted
lessons (latest-accepted dropped first), verbatim, in the P12 format at the start of the prompt. If none are
accepted, the agent gets nothing. Text the guide writes never reaches the agent.

The guide runs once per agent run (so the 5 runs of a task can get different lessons, as the agent's sampling
differs too).

## Arms

| Arm | Store | Retrieval | New runs |
| --- | --- | --- | --- |
| A0, M (BM25 top-3), C1 (all own lessons) | clean | reused from P12, same server setup | 0 |
| E | clean | embedding top-3, no guide | 30 |
| G0 | clean | embedding top-5, guide filters, no retry | 30 |
| G1 | clean | guide, up to 1 retry | 30 |
| G3 | clean | guide, up to 3 retries | 30 |
| E-p | poisoned | embedding top-3 | 20 |
| G3-p | poisoned | guide, up to 3 retries | 20 |

Tasks: the 6 Silent Failures tasks of P12 (TF01, TF02, TF03, TF05 failing; TF04, TF06 leak-free as no-harm
checks). Poisoned arms on the 4 failing tasks only. 5 runs per task. 160 new runs. DSBench is dropped: in P12 its
lessons carried only right/wrong and nothing moved.

## Measures

1. Targeted checks on the 4 failing tasks, pooled share of check-runs passed (as P12), plus TF05 leaking columns
   kept, plus test scores.
2. Retrieval quality per run: how many of the lessons shown to the agent state the planted fix (lesson audit
   labels from P12, extended to any lesson the arms show), and how many are wrong lessons.
3. Trust: per poisoned run, was a wrong lesson retrieved; accepted by the guide; shown to the agent; and did the
   final model drop the named column (hand-checked against code, as in P4).
4. Cost: guide calls, guide tokens, retries used, and agent tokens per run.
5. Harm: TF04/TF06 checks and scores vs A0.

## Dry run of retrieval (before any agent run)

Embedding retrieval is deterministic, so I ran it alone (no model calls) before fixing the predictions. Output:
`quick_runs/results/P13/dryrun_embedding_top5.txt` (top 5 per task; own-task flag, wrong flag, title).
1. Dense retrieval is better than BM25 here. Its top 3 holds a lesson naming the fix for TF01 ("Check for Class
   Imbalance", "Address Class Imbalance"), TF02 ("Inspect data for unit suffixes", twice) and TF05 ("Identify and
   Remove Leakage Features", rank 3). For TF03 the top 5 has "Incorporate Causal Reasoning" at rank 4, and the
   rest are generic or contradicting ("Verify Feature Inclusion Requirements").
2. Near-duplicates remain: TF02's top 5 has the same unit-suffix lesson three times; TF01's has stratified
   splitting twice.
3. Poisoned store: a wrong lesson is rank 1 for TF01 and TF05 (TF05 also rank 4), rank 5 for TF02, and not in the
   top 5 for TF03. So E-p shows a wrong lesson on TF01 and TF05 (10 runs); G3-p's guide sees one on TF01, TF02
   and TF05 in round 0.
So the gap left for the guide is smaller than BM25's, and predictions 1, 2 and 5 below were set after this dry run.

## Expected direction

1. E is clearly better than M (0.125) but below C1 (0.75): pooled between 0.30 and 0.60. Fix lessons are retrieved
   for TF01, TF02 and TF05, but next to duplicates and generic lessons, and not for TF03.
2. Guided retrieval beats E: G3 pooled at least 0.10 higher than E, mostly from TF03 (where only a retry can reach
   the fix lessons) and from replacing duplicates.
3. More budget helps or holds: G0 <= G1 <= G3 (pooled), with G3 at least 0.10 above G0.
4. G3 stays at or below C1 (0.75). C1 is the upper bound for this store.
5. Poisoned store, E-p: a wrong lesson is shown in exactly the 10 TF01/TF05 runs (deterministic), and the named
   column is dropped in at least 8 of those 10 (P4 behaviour).
6. Poisoned store, G3-p: the guide does NOT reliably filter wrong lessons. It accepts a retrieved wrong lesson in
   at least half of the runs where one is retrieved, because it judges fit, not truth. (If it filters most of
   them, that is the stronger trust result.)
7. No harm: TF04/TF06 test scores within 0.01 of A0 in every arm.
8. Cost: the guide adds at most 25% to the prompt tokens of a run at G3.

If 2 and 3 hold, the guided, budget-scaled retrieval idea holds on these tasks. If 6 holds, the paper reports
that a usefulness guide is not a truth check, and memory needs a separate verification step (the trust point).

## Limits stated in advance

- 4 failing tasks, 5 runs each. Small; a pilot for a workshop paper, not a benchmark result.
- Same-task memory with evaluator-informed lessons: the best case for any memory. Transfer is not tested.
- The guide is the same model as the agent; it is not checked against a second model.
- The wrong lessons are hand-written by me, in a style that may differ from the agent's own lessons.
- A0, M and C1 are reused from P12 (run on 2026-11-15 on the same server configuration, at different concurrency).
